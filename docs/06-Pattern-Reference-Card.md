# Completion Theater: field card

The HUSTEF five-pattern field guide, adapted for tonight's investigation.

| Pattern | The claim | The check |
| --- | --- | --- |
| Ghost Database | 'The data is saved.' | Read the real record, restart the process, query again and check the app's state path. |
| Metric Theater | 'Excellent coverage. All tests pass.' | Locate the fresh tool output. Check scope, denominator, skipped work and exit status. No metric is required if it was not measured. |
| Test Theater | 'The test proves it works.' | Read the assertion. Deliberately break the relevant behavior or expected result in a disposable copy. The check must fail. |
| False Positives | 'Success.' | Inspect the raw response and exit code. Trigger a known failure and confirm the wrapper propagates it. |
| Uncommitted Illusion | 'The implementation is finished.' | Start from the exact delivered commit or checksummed archive. Check that the demonstrated source and tests are present. |

## Three reminders

An agent's conclusion is a claim to investigate. An executed check has a scope. A clean result means 'not observed within these checks', not 'no defects exist'.

A bug is not automatically completion theater. Name the pattern only when the evidence supports that interpretation. Discuss the artifact and the claim, not the competence of its authors.
